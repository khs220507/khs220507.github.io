UART는 MCU에서 디버깅 로그를 출력하거나 다른 모듈과 데이터를 주고받을 때 사용하는 직렬 송수신 주변장치입니다. 공유 클록 선 없이 각 장치의 설정된 비트 타이밍으로 통신하는 **비동기 방식**입니다. TX와 RX를 각각 사용하면 송신과 수신을 동시에 할 수 있습니다. [Microchip UART 설명](https://www.microchip.com/en-us/products/microcontrollers/8-bit-mcus/peripherals/communication-connectivity/uart)

## 1. 연결은 TX와 RX를 교차한다

```text
MCU A                    MCU B
TX  -------------------> RX
RX  <------------------- TX
GND -------------------- GND
```

일반적인 비절연 로직 레벨 연결 기준입니다. 두 장치의 전압 호환성과 공통 기준 전위를 확인해야 합니다. MCU UART 핀을 RS-232나 RS-485 배선에 바로 연결하는 것은 다른 문제이며, 해당 전기 규격에 맞는 트랜시버가 필요합니다.

## 2. 115200, 8N1은 무엇인가

대표적인 설정 표기인 `115200 8N1`은 다음과 같이 읽습니다.

| 설정 | 의미 |
| --- | --- |
| 115200 | 초당 115200 심볼의 보율. 일반적인 2레벨 UART에서는 비트율과 수치가 같음 |
| 8 | 데이터 비트 8개 |
| N | 패리티 없음 |
| 1 | 정지 비트 1개 |

```text
유휴 HIGH → 시작 LOW → D0 D1 D2 D3 D4 D5 D6 D7 → 정지 HIGH
```

8N1에서는 데이터 한 바이트에 시작·정지 비트가 붙어 총 10비트가 필요합니다. 따라서 연속 전송을 가정한 115200bps의 데이터 처리량 상한은 $115200 / 10 = 11520$바이트/초입니다. 실제 처리량에는 메시지 구분자와 전송 간격도 영향을 줍니다. 이 값은 프레임 길이를 이용한 계산 예입니다.

양쪽의 보율·데이터 비트·패리티·정지 비트를 맞춰야 합니다. 허용 가능한 클록 오차는 MCU와 수신 방식에 따라 확인해야 합니다. [Microchip USART 소개](https://developerhelp.microchip.com/xwiki/bin/view/products/mcu-mpu/8-bit-avr/structure/usart-intro/)

## 3. 바이트 수신과 메시지 완성은 다르다

예를 들어 `TEMP,25\n`을 보내도 수신 콜백 한 번에 전체 문자열이 들어온다고 가정하면 안 됩니다. 아래는 동작을 설명하기 위한 예시입니다.

```text
첫 수신:  TEM
다음 수신: P,25\n
버퍼 결합: TEMP,25\n
줄바꿈 확인 → 메시지 하나 분리 → 값 해석
```

메시지 규칙으로 줄바꿈, 고정 길이, 길이 필드 등을 정하고 수신 버퍼에서 경계를 판단합니다. 인터럽트나 DMA는 바이트를 옮기는 수단이며, 메시지 파싱은 별도로 필요합니다. 버퍼가 꽉 찼을 때 처리와 불완전한 메시지의 제한 시간도 정해 두면 문제를 추적하기 쉽습니다.

## 4. 데이터가 깨질 때 확인 순서

1. TX·RX 교차 연결, GND와 전압 수준을 확인합니다.
2. 양쪽 보율과 프레임 설정을 비교합니다.
3. 로직 애널라이저에서 비트 폭과 정지 비트를 확인합니다.
4. 수신 오버런, 버퍼 용량, 소비 속도를 확인합니다.
5. 메시지가 나뉘거나 여러 개 붙어서 도착하는 경우를 테스트합니다.

실험에서는 먼저 짧은 고정 문자열을 주고받고, 이후 메시지 길이와 전송 빈도를 늘리는 방식으로 원인을 좁힐 수 있습니다.

## 경험과 연결

STM32 프로젝트에서 UART·DMA 수신과 수신 버퍼 처리를 다뤘습니다. 장비 연동에서는 데이터 수신 자체뿐 아니라, 수신 데이터를 완성된 메시지로 분리하는 과정을 함께 봐야 합니다.
