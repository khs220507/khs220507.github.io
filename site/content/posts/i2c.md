I2C는 **SDA 데이터 선과 SCL 클록 선**을 공유하며 주소로 대상 장치를 구분하는 동기식 버스입니다. 센서처럼 짧은 제어 값이나 측정값을 주고받는 연결에서 자주 볼 수 있습니다.

## 1. 풀업 저항이 필요한 이유

일반적인 양방향 I2C에서 장치는 오픈드레인 출력으로 선을 LOW로 당기거나 놓아줍니다. 선을 놓았을 때 HIGH가 되도록 SDA·SCL에 풀업 저항을 사용합니다.

```text
VDD -- 저항 -- SDA ---- MCU / 센서 A / 센서 B
VDD -- 저항 -- SCL ---- MCU / 센서 A / 센서 B
GND ------------------ 공통 기준
```

저항값은 버스 정전용량, 상승 시간과 장치의 LOW 출력 능력을 고려해 결정합니다. 모듈 여러 개에 풀업이 이미 있다면 병렬로 연결되는 효과도 확인해야 합니다.

## 2. 주소·ACK·데이터

7비트 주소를 사용하는 쓰기 전송의 기본 흐름은 다음과 같습니다.

```text
START → 주소 + W → ACK → 데이터 → ACK → STOP
```

주소와 읽기/쓰기 비트 뒤에 수신 측의 ACK/NACK가 옵니다. 데이터도 8비트 전송 후 응답 비트가 이어집니다. ACK는 해당 바이트에 대한 응답이며 전체 응용 작업의 완료를 뜻하지는 않습니다.

레지스터 주소를 먼저 쓰고 읽는 장치는 아래 형태를 사용할 수 있습니다. 정확한 절차는 장치 데이터시트로 확인합니다.

```text
START → 주소+W → ACK → 레지스터 → ACK
Repeated START → 주소+R → ACK → 데이터 → NACK → STOP
```

마지막 읽기 바이트 뒤에서는 컨트롤러가 NACK로 읽기 종료를 알립니다. 일반적인 속도 모드는 Standard 100kbit/s, Fast 400kbit/s, Fast-mode Plus 1Mbit/s이며 모든 장치가 모든 모드를 지원하지는 않습니다. 위 버스 동작과 전기적 조건은 [NXP I2C 규격 UM10204](https://cache.nxp.com/docs/en/user-guide/UM10204.pdf)를 기준으로 정리했습니다.

## 3. 주소 표기에서 실수하기 쉬운 부분

설명용으로 7비트 주소가 `0x50`인 가상의 장치를 생각해 봅니다. 주소 뒤에 R/W 비트를 붙이면 전송되는 주소 바이트는 쓰기 `0xA0`, 읽기 `0xA1`입니다.

```text
7비트 주소:       1010000       = 0x50
쓰기 주소 바이트: 1010000 0     = 0xA0
읽기 주소 바이트: 1010000 1     = 0xA1
```

이는 비트 조합을 보여 주는 계산 예입니다. API가 7비트 주소를 받는지, 왼쪽으로 이동된 값을 받는지 확인한 뒤 전달해야 합니다. 숫자만 보고 주소를 한 번 더 이동하면 다른 장치를 지정하게 됩니다.

## 4. 센서 값이 읽히지 않을 때

1. 센서 전원과 공통 GND, 풀업 전압을 확인합니다.
2. 유휴 상태에서 SDA·SCL이 HIGH인지 봅니다.
3. 주소 전송 직후 ACK가 있는지 확인합니다.
4. 주소 선택 핀과 API의 주소 표현을 비교합니다.
5. 레지스터 주소·읽기 길이·반복 START 조건을 확인합니다.
6. 수신에 성공했어도 데이터의 부호, 바이트 순서, 환산 계수를 점검합니다.

ACK가 없으면 먼저 연결과 주소를 좁혀 보고, ACK가 있는데 값만 이상하면 레지스터와 데이터 해석을 확인하는 식으로 나누면 도움이 됩니다.

## 경험과 연결

STM32 통합 프로젝트에서는 MPU6050의 7비트 주소 `0x68`과 레지스터 번호를 전달해 센서 값을 읽는 코드를 작성했습니다. 아래처럼 제한 시간을 명시하고 결과를 오류로 변환했습니다.

```c
static const char *read_byte(uint8_t reg, uint8_t *value)
{
    return bus_error(i2c1_read_register(0x68U, reg, value, 10000U));
}
```

여러 바이트를 읽은 뒤에는 상위·하위 바이트를 결합해 부호 있는 가속도 값으로 해석했습니다. 통신 성공과 데이터 변환 결과는 따로 확인할 항목입니다. 이 코드는 보관함의 펌웨어 면접 자료에 정리된 구현 발췌이며, 전체 통합 프로젝트의 모든 동작을 현장 검증했다는 뜻은 아닙니다.
