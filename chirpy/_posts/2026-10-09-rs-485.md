[UART](/posts/uart/)는 바이트의 시작·데이터·정지 비트를 만드는 주변장치이고, RS-485는 장치 사이 배선에서 차동 신호를 사용하는 **전기적 인터페이스**입니다. STM32의 UART 핀만으로 RS-485 버스에 직접 연결하지 않고, 송수신 트랜시버를 거칩니다. RS-485 자체는 명령 형식, 주소, 재전송 방법을 정해 주지 않습니다. [TI의 RS-485 기초 설명](https://www.ti.com/document-viewer/lit/html/SSZTCS4/GUID-DE4FDB29-B8E5-472F-B85F-1B072D552416)

## UART와 RS-485가 만나는 위치

```text
STM32 UART TX/RX ↔ RS-485 트랜시버 ↔ 차동 배선 ↔ 상대 장치
                                  A/B
```

2선식 반이중 배선은 한 쌍의 선을 송신과 수신에 번갈아 씁니다. 이 구성에서는 누가 언제 송신할지 응용 프로토콜에서 정해야 합니다. 4선식 전이중 구성도 있으므로 실제 장치의 배선을 먼저 확인합니다.

| 구간 | 확인할 것 |
| --- | --- |
| UART | 보율, 데이터 비트, 패리티, 정지 비트 |
| 트랜시버 | 송신 활성화·수신 활성화 핀과 전환 시점 |
| 버스 | 선로 극성, 공통 기준, 종단과 바이어스 |
| 메시지 | 명령 구분자, 길이, 응답 제한 시간 |

## 송신 방향 제어

반이중 트랜시버는 보통 송신 활성화 핀인 DE와 수신 활성화 핀인 `/RE`를 가집니다. 대표적인 흐름은 **송신 방향 전환 → UART 데이터 전송 → 마지막 정지 비트까지 완료 확인 → 수신 방향 복귀**입니다. 단순히 UART 송신 함수가 데이터를 버퍼에 넣은 시점과 실제 선로에서 송신이 끝난 시점은 다를 수 있습니다. 핀의 활성 수준과 제어 순서는 사용하는 트랜시버 데이터시트가 기준입니다.

```text
수신 대기 ── 명령 준비 ── DE 활성화 ── 바이트 송신
                                      │
                                전송 완료 확인
                                      ↓
                               DE 해제 · 응답 대기
```

상대가 말하기 전에 버스를 놓지 않거나, 너무 일찍 수신으로 돌아가 마지막 바이트가 잘리면 간헐적인 오류가 생깁니다. [TI의 RS-485 트랜시버 자료](https://www.ti.com/lit/wp/slla545/slla545.pdf)

## 종단 저항과 극성

긴 배선이나 빠른 에지에서는 반사로 파형이 흔들릴 수 있습니다. 일반적으로 버스 양 끝에서 케이블 특성 임피던스에 맞춘 종단을 검토하며, 모든 장치에 종단 저항을 다는 것은 피합니다. 120Ω은 흔한 예시지만 보드에 이미 저항이 있는지와 케이블 조건을 먼저 확인해야 합니다. 유휴 상태를 안정시키는 바이어스도 종단과 별도로 검토합니다. [TI의 종단 저항 설명](https://www.ti.com/document-viewer/lit/html/SSZTB23A/GUID-B7704918-202D-4557-B6E0-F0BB82D05C97)

장치마다 A/B 명칭을 반대로 표기하는 사례가 있으므로 라벨만 믿기보다 데이터시트의 차동 전압 정의와 실제 파형을 기준으로 연결을 확인합니다.

## 프로젝트에서 처리한 메시지

STM32 통합 프로젝트의 RS-485 경로에서는 UART 수신 측이 완성된 줄을 전달하고, 상위 명령 파서가 한 바이트씩 소비하도록 작성했습니다. TCP 경로와 RS-485 경로를 번갈아 확인해, 명령을 받은 경로로 응답하는 코드도 정리되어 있습니다.

```c
void protocol_send_pong(void)
{
    protocol_write_text("OK,PING,PONG\r\n");
}
```

위 ASCII·CRLF 응답은 **프로젝트의 응용 메시지 형식**입니다. RS-485 표준이 PING이나 줄바꿈을 요구하는 것은 아닙니다. 보관함의 STM32 핵심 코드 노트에는 RS-485 경로의 코드 발췌와 제한 시간이 남아 있습니다. 통합 프로젝트에서 모든 센서 명령을 실기로 검증했다고 확대해서 해석하지 않습니다.

## 통신이 불안정할 때

1. UART 프레임 설정과 트랜시버 전압을 확인합니다.
2. A/B 배선과 공통 기준을 확인합니다.
3. DE·`/RE` 전환 시점을 로직 애널라이저로 확인합니다.
4. 버스 양 끝 종단과 바이어스 중복을 확인합니다.
5. 바이트가 왔다면 줄바꿈·길이·체크섬 등 메시지 규칙을 점검합니다.
