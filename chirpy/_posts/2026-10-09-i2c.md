## 기본 개념

I2C는 `SCL` Clock 선과 `SDA` Data 선을 여러 장치가 함께 사용하는 동기식 통신 방식이다. `07_I2C_Pending` 프로젝트에서는 STM32가 Controller가 되어 I2C1 Bus의 7-bit 주소 `0x01`부터 `0x7F`까지 응답 여부를 확인한다.

PB8과 PB9는 `GPIO_MODE_AF_OD`로 설정되어 있어 선을 직접 HIGH로 밀어 올리지 않는 Open-drain 방식이다. 현재 내부 Pull-up은 `GPIO_NOPULL`이므로 실제 배선에서는 SCL과 SDA에 외부 Pull-up 저항을 3.3V로 연결해야 한다.

| 신호 | STM32 Pin | 설정 |
|---|---|---|
| I2C1_SCL | PB8 | `GPIO_AF4_I2C1`, Open-drain |
| I2C1_SDA | PB9 | `GPIO_AF4_I2C1`, Open-drain |
| 통신 속도 | - | Standard-mode 100kHz |
| 주소 방식 | - | 7-bit |
| 결과 출력 | USART2 | 115200bps |

## 구현 목표

- I2C1을 PB8(SCL), PB9(SDA), 100kHz로 초기화한다.
- 7-bit 주소 범위를 순회하며 장치의 ACK 응답을 확인한다.
- 응답한 주소만 USART2의 `printf()` 출력으로 표시한다.

현재 소스 구현과 Debug 빌드는 완료되었다. Flash와 Verify 기록은 있지만, 실제 I2C 장치의 주소 응답은 아직 확인되지 않았다.

## 핵심 코드

### I2C1 초기화

```c
I2C_HandleTypeDef hi2c1;

hi2c1.Instance = I2C1;
hi2c1.Init.ClockSpeed = 100000;
hi2c1.Init.DutyCycle = I2C_DUTYCYCLE_2;
hi2c1.Init.OwnAddress1 = 0;
hi2c1.Init.AddressingMode = I2C_ADDRESSINGMODE_7BIT;
hi2c1.Init.DualAddressMode = I2C_DUALADDRESS_DISABLE;
hi2c1.Init.OwnAddress2 = 0;
hi2c1.Init.GeneralCallMode = I2C_GENERALCALL_DISABLE;
hi2c1.Init.NoStretchMode = I2C_NOSTRETCH_DISABLE;

if (HAL_I2C_Init(&hi2c1) != HAL_OK)
{
    Error_Handler();
}
```

### 주소 스캔

```c
static void I2C_Scan(void)
{
    uint16_t address;

    for (address = 1U; address < 128U; address++)
    {
        if (HAL_I2C_IsDeviceReady(&hi2c1,
                                  (uint16_t)(address << 1U),
                                  2U,
                                  10U) == HAL_OK)
        {
            printf("I2C device: 0x%02X\r\n", address);
        }
    }
}
```

## 코드 설명

`HAL_I2C_Init()`은 `hi2c1.Init`에 저장한 100kHz, 7-bit Addressing 등의 설정을 I2C1에 적용한다. 이 과정에서 `HAL_I2C_MspInit()`이 PB8/PB9 Alternate Function과 I2C1 Clock을 준비한다.

Scanner의 `address`는 사람이 읽는 7-bit 주소다. STM32 HAL의 `HAL_I2C_IsDeviceReady()`에는 이 값을 한 bit 왼쪽으로 이동한 `(address << 1U)`를 전달한다. 최하위 bit 자리는 I2C 전송의 Read/Write bit에 해당하기 때문이다. 출력할 때는 이동 전 주소를 사용하므로 Terminal에는 `0x68` 같은 7-bit 주소가 표시된다.

| 인자 | 현재 값 | 의미 |
|---|---:|---|
| I2C Handle | `&hi2c1` | 검사할 I2C1 설정과 상태 |
| Device Address | `address << 1U` | HAL에 전달하는 주소 형식 |
| Trials | `2U` | 준비 여부 확인 시도 횟수 |
| Timeout | `10U` | 각 확인의 제한 시간 10ms |

`HAL_OK`는 대상 주소에서 응답을 받았다는 뜻이다. 그 외 상태는 현재 Scanner에서 출력하지 않고 다음 주소로 넘어간다. 이 구현은 Polling 방식이며 I2C IRQ나 Callback을 사용하지 않는다.

## 동작 흐름

1. `HAL_Init()`과 Clock 설정을 수행한다.
2. `MX_I2C1_Init()`에서 I2C1을 100kHz로 초기화한다.
3. USART2를 115200bps로 초기화하고 `I2C scanner ready`를 출력한다.
4. 7-bit 주소 `0x01`부터 `0x7F`까지 준비 여부를 검사한다.
5. ACK가 확인된 주소만 `I2C device: 0xXX` 형식으로 출력한다.
6. 스캔이 끝나면 Main Loop에서 1초 Delay를 반복하며 다시 스캔하지 않는다.

## 배선과 확인 상태

| 연결 | 대상 |
|---|---|
| PB8 | I2C 장치 SCL |
| PB9 | I2C 장치 SDA |
| 3.3V | 장치 전원과 SCL/SDA 외부 Pull-up |
| GND | STM32와 장치의 공통 GND |

NUCLEO-F401RE에 `07_I2C.elf`를 다운로드하고 Verify까지 완료했으며, COM3에서 `I2C scanner ready` 출력은 확인했다. 그러나 I2C 주소 응답은 확인하지 못했고 시작 문구가 반복 출력되었다. 따라서 프로젝트 폴더를 `07_I2C_Pending`으로 표시했다. 현재 기록할 수 있는 상태는 **구현 완료, 빌드 완료, Flash·Verify 완료, 실제 I2C 응답 추가 확인 필요**이다. GY-521 모듈을 준비한 뒤 주소 스캔부터 다시 검증한다.

## 배운 점

- I2C는 SCL과 SDA 두 선을 사용하며 Open-drain 신호에는 Pull-up이 필요하다.
- STM32 HAL에 7-bit 장치 주소를 전달할 때는 한 bit 왼쪽으로 이동한다.
- `HAL_I2C_IsDeviceReady()`를 Polling으로 호출해 주소별 ACK 응답을 확인할 수 있다.
- 현재 Scanner는 시작할 때 한 번만 실행되며 I2C Interrupt와 Callback을 사용하지 않는다.

## 한 줄 정리

I2C 주소 스캐너는 PB8/PB9의 I2C1 Bus에서 7-bit 주소를 순회하고 ACK가 확인된 주소만 UART로 출력한다.
