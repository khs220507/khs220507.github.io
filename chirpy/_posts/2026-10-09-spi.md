SPI는 컨트롤러가 생성하는 클록에 맞춰 데이터를 교환하는 동기식 직렬 통신입니다. 기본 4선 구성에서는 송신과 수신 경로가 분리되어 전이중 전송이 가능합니다. 실제 명령 구성과 최대 클록은 대상 장치의 규격을 따릅니다. [Microchip SPI 개요](https://www.microchip.com/en-us/products/microcontrollers/8-bit-mcus/peripherals/communication-connectivity/spi)

## 1. 네 신호의 역할

| 신호 | 역할 |
| --- | --- |
| SCK | 컨트롤러가 만드는 클록 |
| MOSI | 컨트롤러에서 대상 장치로 전달하는 데이터 |
| MISO | 대상 장치에서 컨트롤러로 전달하는 데이터 |
| CS / SS | 통신할 장치 선택. 보통 LOW 활성 |

SDI·SDO라고 표기된 핀은 **해당 장치 관점**의 입력·출력입니다. MOSI·MISO 이름과 혼동하지 말고 방향을 확인합니다. 여러 장치를 연결할 때는 보통 SCK·MOSI·MISO를 공유하고 장치마다 CS를 둡니다.

## 2. CPOL과 CPHA

CPOL은 유휴 클록 수준, CPHA는 샘플링할 에지를 정합니다. 첫 번째·두 번째 에지는 유휴 상태에서 클록이 움직이기 시작한 뒤의 순서입니다.

| 모드 | CPOL | CPHA | 유휴 SCK | 샘플링 에지 |
| --- | --- | --- | --- | --- |
| 0 | 0 | 0 | LOW | 첫 번째, 상승 |
| 1 | 0 | 1 | LOW | 두 번째, 하강 |
| 2 | 1 | 0 | HIGH | 첫 번째, 하강 |
| 3 | 1 | 1 | HIGH | 두 번째, 상승 |

CS를 활성화한 뒤 명령·주소·데이터를 주고받고 해제하는 구성이 일반적입니다. 여러 바이트 동안 CS를 유지해야 하는 장치도 있습니다. SPI에는 공통 ACK 절차가 없으므로 성공 여부는 장치별 상태나 읽은 값으로 확인합니다. [Microchip SPI 신호·모드 설명](https://developerhelp.microchip.com/xwiki/bin/view/applications/SPI/)

## 3. 읽을 때도 클록이 필요하다

컨트롤러가 수신하려면 클록을 생성해야 합니다. 보통 송신 경로에 더미 값을 넣어 클록을 만들면서 MISO 값을 읽습니다. 필요한 더미 바이트 수와 값은 데이터시트로 확인합니다.

아래는 특정 칩의 명령이 아닌 설명용 의사 코드입니다.

```text
CS 활성화
읽기 명령 전송
주소 전송
규격에 필요한 더미 사이클 생성
수신 길이만큼 클록 생성하며 데이터 읽기
전송 완료 확인
CS 해제
```

명령을 전송하는 동안에도 수신 레지스터에 값이 들어올 수 있지만, 그 값이 유효한 응답이라는 보장은 없습니다. 어떤 구간의 수신값을 사용할지 장치 프로토콜에 맞춰 판단합니다.

## 4. 값이 0x00 또는 0xFF로만 보일 때

1. 전원·GND·전압 수준과 CS 대상이 맞는지 확인합니다.
2. SCK가 실제로 출력되는지 확인합니다.
3. MOSI·MISO 방향과 핀의 대체 기능 설정을 확인합니다.
4. 모드, 비트 순서, 전송 단위와 클록 속도를 확인합니다.
5. CS가 명령 도중 해제되지 않는지 봅니다.
6. 주소 형식과 더미 사이클을 확인합니다.

`0xFF`가 반복된다는 관측만으로 원인을 단정하지 않습니다. MISO가 구동되지 않는 경우와 실제 응답값인 경우를 파형으로 구분해야 합니다.

## 경험과 연결

STM32 통합 프로젝트에서 W5500 레지스터 읽기를 위해 SPI 프레임 송수신 코드를 작성했습니다. 아래 함수는 W5500 버전 레지스터 `0x0039`의 한 바이트를 읽도록 하위 함수에 요청합니다.

```c
spi2_result_t w5500_read_version(uint8_t *version, uint32_t timeout_us)
{
    return w5500_read(0U, 0x0039U, version, 1U, timeout_us);
}
```

버전 읽기는 SPI 배선·모드·칩 선택을 확인할 출발점입니다. 이후 IP와 소켓 설정을 확인해야 네트워크 통신까지 점검할 수 있습니다. 프로젝트 코드의 기능별 구현과 실제 장비 검증 범위는 구분해서 봐야 합니다.
