**AI 활용의 핵심은 원하는 결과, 판단에 필요한 자료, 사용할 수 있는 기능을 연결하는 것입니다.** 모델을 직접 개발하지 않더라도 이 구조를 이해하면 AI에 맡길 범위와 결과를 확인하는 기준이 분명해집니다.

모델 자체의 원리는 [인공지능 핵심 개념](/posts/ai-core-concepts/)에서, MCP·에이전트·RAG의 연결 구조는 [AI 활용 심화 개념](/posts/ai-usage-advanced-concepts/)에서 다룹니다. 이 글은 특정 제품의 메뉴나 설치 절차보다 여러 AI 도구에 공통으로 적용되는 개념에 초점을 맞춥니다.

## 1. AI를 활용한다는 것

대화형 AI에서 보이는 답변은 전체 기능의 일부입니다. 애플리케이션은 모델에 지시와 자료를 전달하고, 필요한 도구를 실행하며, 결과를 다시 모델에 제공할 수 있습니다.

| 구성 | 역할 |
| --- | --- |
| 모델 | 제공된 정보를 바탕으로 판단하고 출력 생성 |
| AI 애플리케이션 | 대화·자료·도구 실행 관리 |
| 도구 | 외부 정보를 읽거나 실제 작업 수행 |
| 사용자 | 목표·범위·완료 기준 결정 |

모델이 도구 호출을 요청하면 애플리케이션이나 서비스가 이를 실행하는 구조가 일반적입니다. 모델의 답변 생성과 외부 시스템에서의 작업 실행은 서로 구분됩니다. [Anthropic: 도구 사용 구조](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)

## 2. 프롬프트 — 원하는 결과를 전달하는 지시

**프롬프트(Prompt)**는 AI에 제공하는 요청과 지시입니다. 명확한 요청은 AI가 추측해야 할 부분을 줄입니다.

| 전달할 내용 | 의미 |
| --- | --- |
| 목표 | 무엇을 완성해야 하는지 |
| 대상과 배경 | 누구를 위한 작업이며 어떤 맥락인지 |
| 범위 | 어디까지 다룰지 |
| 제약 | 지켜야 할 조건과 제외할 내용 |
| 출력 형식 | 결과물을 어떤 형태로 받을지 |
| 완료 기준 | 무엇을 충족해야 끝난 것으로 볼지 |

긴 지시문 자체보다 필요한 조건이 빠짐없이 전달되는 것이 중요합니다. 역할을 부여하는 것만으로 부족한 자료가 채워지거나 사실성이 보장되지는 않습니다. [Anthropic: 명확한 지시와 프롬프트 구성](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)

## 3. 문맥 — AI가 실제로 참고하는 정보

**문맥(Context)**은 현재 판단에 사용되는 지시, 대화 내용, 문서, 도구 결과 등의 정보입니다. 프롬프트가 작업의 방향을 정한다면, 문맥은 판단의 근거를 제공합니다.

AI가 접근할 수 있는 자료 전체와 현재 모델에 전달된 정보는 같지 않습니다. 연결된 저장소가 있어도 필요한 문서를 검색하거나 읽는 과정이 필요할 수 있습니다.

문맥에는 길이 제한이 있으며, 관련 없는 정보를 많이 넣으면 중요한 조건이 묻힐 수 있습니다. 따라서 자료의 양보다 **현재 작업과의 관련성, 최신성, 출처의 명확성**이 중요합니다. [Anthropic: 문맥 관리](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)

## 4. 도구 — 답변을 실제 작업으로 연결하는 기능

**도구(Tool)**는 AI가 호출할 수 있도록 정의된 기능입니다. 도구에는 이름, 설명, 입력 형식 등이 있으며, 모델은 이를 바탕으로 필요한 호출을 구성합니다.

```mermaid
flowchart LR
    A[모델의 도구 호출 요청] --> B[실행 환경의 도구 실행]
    B --> C[실행 결과 반환]
    C --> D[모델의 후속 판단]
```

도구를 사용할 수 있는지, 어떤 입력을 받는지, 실제 실행에 성공했는지는 각각 다릅니다. **도구 호출 요청은 실행 완료가 아니며, 실행 결과를 받아야 다음 판단이 가능합니다.** [Anthropic: 도구 호출과 실행](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)

## 5. 스킬 — 반복할 작업 방법을 묶은 지식

**스킬(Skill)**은 특정 작업의 수행 방법과 관련 자료를 재사용할 수 있도록 묶은 것입니다. 이 글에서 스킬은 공개 형식인 **Agent Skills**를 기준으로 설명합니다.

Agent Skills는 `SKILL.md`에 이름·설명과 작업 지침을 담고, 필요하면 스크립트·참고 문서·템플릿을 함께 포함합니다. 반복되는 절차와 결과 기준을 매번 대화에 다시 설명하는 부담을 줄일 수 있습니다.

스킬은 모델을 새로 학습시키는 기능이 아닙니다. 작업 시 지침과 자료를 제공하는 방식이며, 필요한 도구나 실행 환경이 있어야 지침에 포함된 작업을 수행할 수 있습니다. [Agent Skills: 개요](https://agentskills.io/home)

## 6. 프롬프트·도구·스킬·MCP의 차이

| 개념 | 중심 역할 |
| --- | --- |
| 프롬프트 | 이번 작업의 요구사항 전달 |
| 문맥 | 판단에 필요한 정보 제공 |
| 도구 | 호출 가능한 실제 기능 제공 |
| 스킬 | 재사용할 작업 지침과 자료 제공 |
| MCP | 외부 기능과 정보를 연결하는 통신 방식 표준화 |

**MCP(Model Context Protocol)**는 AI 애플리케이션과 외부 프로그램이 기능과 정보를 주고받기 위한 공개 프로토콜입니다. 도구를 제공하는 연결 방식 중 하나이며, 모든 도구가 반드시 MCP를 사용하는 것은 아닙니다. [MCP: 아키텍처](https://modelcontextprotocol.io/docs/learn/architecture)

스킬은 MCP로 연결된 도구를 사용하는 방법을 담을 수 있습니다. 이때 스킬은 작업 절차를, MCP는 연결 규약을 담당합니다. 두 기능은 함께 사용할 수 있지만 서로 같은 개념은 아닙니다. [Agent Skills: 개요](https://agentskills.io/home), [MCP: 서버 기능](https://modelcontextprotocol.io/docs/learn/server-concepts)

## 7. 작업을 맡기는 범위

AI에 맡기는 범위는 답변 생성에서 여러 단계의 실행까지 달라질 수 있습니다.

| 필요한 처리 | 중심이 되는 구성 |
| --- | --- |
| 주어진 자료의 해석과 정리 | 프롬프트·문맥 |
| 외부 정보 조회와 실제 변경 | 도구와 연결 |
| 반복되는 작업 방식의 유지 | 스킬 |
| 정해진 순서에 따른 처리 | 워크플로 |
| 결과에 따라 다음 행동을 선택 | 에이전트 |

여기서 **워크플로**는 미리 정한 흐름으로 작업을 진행하고, **에이전트**는 목표와 중간 결과에 따라 다음 행동을 선택합니다. 제품마다 용어의 범위에는 차이가 있습니다. 기능을 많이 연결하는 것보다 필요한 판단과 실행 범위에 맞추는 것이 중요합니다. [Anthropic: 워크플로와 에이전트](https://www.anthropic.com/research/building-effective-agents)

## 8. 결과를 이해하는 기준

AI가 무엇을 말했다는 사실, 도구가 무엇을 반환했다는 사실, 결과물이 실제로 어떤 상태인지는 구분해서 볼 필요가 있습니다.

| 구분 | 확인하는 내용 |
| --- | --- |
| 설명 | 요청을 어떻게 해석했는지 |
| 근거 | 어떤 자료를 사용했는지 |
| 실행 결과 | 어떤 작업이 성공하거나 실패했는지 |
| 결과물 | 요구사항을 실제로 충족하는지 |

이 구분은 앞서 설명한 지시·정보·실행의 관계를 활용에 적용한 기준입니다. AI에 일을 맡길 때 완료 기준을 정하고, 결과에서는 그 기준을 충족했다는 근거를 확인하면 됩니다.

이 요소들이 장기 작업과 외부 시스템 연결에서 어떻게 결합되는지는 [AI 활용 심화 개념](/posts/ai-usage-advanced-concepts/)에서 이어집니다.
